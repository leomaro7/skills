# Reflect on Sessions

## 概要

過去のセッションのトランスクリプトを再生（リプレイ）し、単一セッションでは見えない パターンを浮かび上がらせ、それを永続メモリ／指示ファイルへの更新提案に変える。
"Dreaming" のローカル版であり、対象は外部のメモリ／指示ファイルであって、モデルは変更しない。

**提案のみ・human-in-the-loop** で動く。
所見を提示し、ユーザーが承認したものだけを書き込む。

## Step 0 — 対象ツールを選び、該当 reference を読む

入力（ログの場所・形式）と出力（メモリの書き方）はツールごとに異なる。
以下を判定し、 対応する reference を読んでから Step 1 以降に進む:

- **Claude Code**（既定）— Claude Code のセッションを振り返る。
  `references/claude-code.md` を読む。
- **GitHub Copilot (VS Code)** — 「Copilot の履歴から」等と指定された場合。
  `references/github-copilot.md` を読む。

ツールが曖昧なら、どちらを対象にするかユーザーに確認する。
reference には、その バリアントのダイジェスト生成コマンドとメモリ反映規約が書かれている。

## Step 1 — ダイジェストを生成する

該当 reference に記載の `scripts/digest_*.py` を実行して、直近セッションの コンパクトなダイジェストを得る（生ログは巨大なので必ずスクリプト経由で読む）。
`--limit`（新しい順のセッション数）は 10 から始め、シグナルが薄ければ広げる。

## Step 2 — 既存のメモリ／指示を読む

reference に記載の保存先（`MEMORY.md` ＋ `memory/`、または `copilot-instructions.md` 等）を 読み、提案を「本当に新しいもの」に絞る。
重複を避け、陳腐化・矛盾した項目も拾う。

## Step 3 — セッション横断のパターンを抽出する

セッション内ではなく**セッションをまたいで**、次を探す:

- **繰り返すミス／手戻り** — 同じエラー・訂正・行き止まりが複数セッションで再発している。
- **収束したワークフロー** — 独立して2回以上たどり着いている手順の並び（手順化の候補）。
- **繰り返される好み／指示** — スタイル・ツール・プロセスについてユーザーが何度も示すもの。
- **恒久的なプロジェクト文脈** — コードや git 履歴から導けない目標・制約・環境の事実。

一度きりの詳細や、リポジトリ・git 履歴・CLAUDE.md／既存指示が既に記録していることは無視する。
提案する価値があるのは、**2つ以上のセッション**に証拠があるパターン（または1回でも 強く明言された指示）に限る。

## Step 4 — 承認のために提案を提示する

所見を **追加 / 更新 / 削除** に分類し、簡潔なリストとして提示する。
各項目について、 提案する内容、（Claude Code なら）`type`、根拠（どのセッションか）を示す。
この時点では何も書かない。
ユーザーが項目ごとに承認・修正・却下できるようにする。

## Step 5 — 承認された変更のみを反映する

承認されたものだけを、該当 reference のメモリ反映規約に従って書き込む。
Claude Code はセッションで提供される最新のメモリ規約が最優先。

## スケジュール実行（任意）

本来の "Dreaming" により近づけたい場合、このスキルは後から `/schedule` で定期実行に 載せられる。
その場合も「提案のみ」の契約は維持すること。
スケジュール実行はレビュー用の 提案リストを出すだけで、メモリ／指示ファイルを黙って書き換えてはならない。
