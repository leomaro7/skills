# Asset Finder（資産探索の司令塔スキル）

社内で企画・資料作成・開発を行うとき、利用できる Claude 資産（カスタムエージェント /
スキル / MCP / Hooks / Instructions / CLAUDE.md など）を探し、厳選して提案し、
再現可能なプロンプトとして残す「司令塔」。**判断と案内に徹する薄いオーケストレーター**で、
カタログの実体や検索の実行処理は外部に委ねる（このスキルは「何を・どの順で・どう判断するか」を持つ）。

## 進め方（チェックリスト・順守）

下記 [1]→[8] を**順に**実行する。ステップを飛ばさない・並べ替えない。
質問と提案の**形式は確定テンプレに従う**（再発明しない）：
[references/templates.md](references/templates.md)。

```
[1] 目的・利用技術をヒアリング
[2] 環境を選ばせる
[3] 作業フェーズを見極める
[4] 社内カタログを検索
[5] 外部を検索（社内に無い分のみ・信頼性チェック）
[6] それでも該当が無ければ新規作成を勧める
[7] フェーズごとに厳選して提案する（表→図→結論）
[8] 承認を取りつつセットアップし、再現プロンプトを生成する
```

## 全体の前提

- **環境は毎回利用者に選ばせる**（自動検出しない）。
- **外部は許可リスト方式**。リスト外は提案せず人間のレビューに回す（[5]）。
- **副作用のある操作（ファイル書き込み・設定変更）は実行前に毎回承認を取る**（[8]）。

---

## [1] 目的・利用技術をヒアリング

環境やフェーズの前に、まず**目的（何を達成したいか）**を聞く。決まっていれば
**利用技術・ツール**（言語 / FW / SaaS / API など）も聞く。これらは [4][5] の
検索キーワードと [7] の絞り込み基準になる。

- **目的**：必須。曖昧なら 1 回だけ具体化を促す（目安：**フェーズと検索キーワードが
  定まる粒度**まで。1〜2 回問うて絞れなければその粒度で進める。深掘りしすぎない）。
- **利用技術**：任意。「未定」でよい。決まっていればその技術向けの資産を優先候補にする。

**目的が漠然のまま進む場合（探りモード）**：単一フェーズを深掘りせず、[7] では
**全フェーズ横断の概観**を出す（各フェーズ代表 1〜2 件、薄いフェーズは「該当なし→[6]」）。
全資産の羅列はしない。利用者が深掘り対象フェーズを選んだら本来の絞り込みに入る。

---

## [2] 環境を選ばせる

利用者に動作環境を尋ねる（質問仕様は [references/templates.md](references/templates.md)）。
スキル・MCP 等は環境ごとに対応範囲も設定方法も違うため、ここが分岐の起点。
「わからない」が選ばれたら、作業内容から候補環境を逆提案する。

---

## [3] 作業フェーズを見極める

どのフェーズかを確認する（質問仕様は [references/templates.md](references/templates.md)）。
フェーズは資産を絞り込むバケツ。粒度は粗く、迷えば複数選ばせる。複数フェーズなら各分を扱う。

**レビュー・品質保証は独立フェーズにしない**。横断的にかかるため、[7] で各フェーズの
提案に「その成果物をレビュー/検証する資産」を添えて扱う。

---

## [4] 社内カタログを検索

**最優先で社内資産を検索する。** 検索手段は環境で異なる。

- **Claude Code**：セッションで既に提示済みの skill / サブエージェント / MCP の一覧を
  一次カタログとして使う（追加取得不要）。
- **社内レジストリ（現状ダミー）**：
  - スキル: https://github.com/leomaro7/skills
  - MCP: https://github.com/leomaro7/mcp

  レジストリが無い環境では、まずカタログ構造の定義が要ると利用者に伝える。

環境・フェーズ・目的・利用技術（[1]）に合致する資産を探す。社内資産は信頼性チェック不要。
ヒットは**現環境での導入状態**で見分ける：提示済み＝「既に利用可能」、レジストリにあるが
未導入＝「採用候補（社内）」。この区別がそのまま [7] の `区分` になる。

---

## [5] 外部を検索（社内に無い分のみ）

社内で見つからなかった分だけ、外部を検索する。**検索先・信頼性基準・レビュー専用枠は
[references/allowlist.md](references/allowlist.md) に従う**（許可リスト外は提案しない）。
検索可能なレジストリ（公式 MCP レジストリ）を一次検索先に据える。

---

## [6] 該当する資産が無い場合

社内にも信頼できる外部にも合致が無いフェーズは、**用途に合わない資産を無理に当てはめず、
新規作成を勧める**。

- 「適した資産は見つかりませんでした」と率直に伝える（中途半端な近似を押し込まない）。
- そのフェーズ向けの新規作成を選択肢として提示（作成手段は環境に合わせる）。
- 作ったら社内カタログへ登録し、次回 [4] で再利用できるよう促す。

---

## [7] フェーズごとに提案する

検索ヒットを羅列せず、**全体のバランスを見て厳選してから**提案する。提案前に見渡す観点：

- **重複の排除**：同役割が複数なら最良の 1 つに絞る。同一資産が複数経路（セッション一覧と
  レジストリのミラー等）でヒットしたら出所をまたいで名寄せし 1 件にする。
- **フェーズの網羅**：穴があれば「該当資産なし」と明示（対応は [6]）。
- **過剰の抑制**：便利程度のものは「任意」に。まず効果の大きい最小セットを中核に。
  「既に利用可能」な資産が多い環境（AWS MCP 群など）では、中核以外は代表に畳むか
  「任意」へ落とし、表が膨らみすぎないようにする。
- **組み合わせの整合**：競合・前提依存があれば注記。
- **レビューの横串**：各フェーズに成果物のレビュー/検証資産があれば添える。

**出力は確定スケルトン（表→図→結論）に従う**：[references/templates.md](references/templates.md)。
中核が「既に利用可能」だけで満たせるなら**新規採用ゼロ**でよい（「追加の資産は不要」と結論）。
最後に、表のどれを採用するか利用者に選んでもらう。

---

## [8] セットアップし、再現用プロンプトを生成する

採用が決まったら、この環境でセットアップし、続いて**他の人が同じ構成を再現できる
プロンプト**を生成する（後者が最終成果物）。

**8-1. セットアップ（承認ゲート必須）**

- 資産ごとに、実行する操作（配置先・設定内容・必要な権限）を先に提示する。
- 副作用のある操作は**実行前に毎回承認を取る**。承認されなかったものは行わず、
  再現プロンプトに「手動対応」として残す。
- 何をどこに設定したか記録する（再現プロンプトの素材）。

**8-2. 再現プロンプトの生成**

実際のセットアップを元に、**他の人が自分の AI に渡して再現させる指示**を生成する
（人間向け手順書にしない）。**確定スケルトンに従う**：[references/templates.md](references/templates.md)。

---

## 設計上の分担（やらないこと）

- **検索の実体は外部**：このスキルが持つのは判断ロジック（順序・信頼性基準・厳選・提案）のみ。
  検索の実行は現状スキル内で `gh` / WebFetch を使うが、将来は MCP に切り出す（下記）。
- **無人セットアップはしない**：副作用操作は必ず承認を挟む（[8-1]）。
- **ロジックは本スキルに集約**：重い検索などだけ将来サブエージェント化。頭脳は共通・ガワだけ環境別。

## 将来拡張（今は実装しない・段階を踏む）

1. **カタログにスキーマを与える**（各資産に phase / 用途 / 出所タグ＝資産マニフェスト）。
   現状は README を読まないと用途判定できず場当たり。これが MCP 化の前提。
2. ダミーリポジトリを正式な社内レジストリへ差し替え。
3. **`asset-catalog` MCP（search / get）**を建て、スキルはそれを呼ぶだけにする。
   環境ごとに異なる検索手段を環境非依存のインターフェースで吸収し、許可リストや
   信頼性チェックもサーバ側へ一元化できる。

## 実行例（Claude Code / 企画フェーズ）

1. **[1]**：「何をしたい？」→「新機能の要件を固め構成案にしたい」。技術は未定→そのまま。
2. **[2]**：環境＝Claude Code。
3. **[3]**：「企画」（必要なら「調査・リサーチ」も）と判断。
4. **[4]**：セッション提示済み skill とダミーレジストリを照合 → 要件整理向け社内 skill が 1 件。
5. **[5]**：図表化 MCP が社内に無い → 許可リストの公式 MCP レジストリに候補。信頼性チェック通過。
6. **[7]**：表→図→結論で提示。社内 skill＝中核、外部 MCP＝任意。利用者が両方採用。
7. **[8]**：MCP 設定の書き込み内容を提示し承認 → 設定。実績から再現プロンプトを生成して手渡す。
